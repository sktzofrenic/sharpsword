# SharpSword

SharpSword is a Bible web app written in Go/Vue with a mobile first focus. 

Goals include high performance search (equivalent or faster to native desktop application), and smooth verse navigation. 

Live Implementation: [https://sharpsword.io](https://sharpsword.io)

## Goals

- Fast search with results returned with each keystroke
- Fast navigation using keyboard to any book/chapter/verse
- Mobile first Progressive Web App (PWA) design with responsive layout for desktop
- Amazing Copy/Paste support with customizable formatting
- Verse highlighting and verse selections with sharing options
- Data export and import for easy transition to self hosting

## Setup

### Prerequisites

- [Go](https://golang.org/doc/install)
- [Node.js](https://nodejs.org/en/download/)
- [PostgreSQL](https://www.postgresql.org/download/)
- [Air](https://github.com/air-verse/air) (optional, for hot reloading the Go server): `go install github.com/air-verse/air@latest`

### Install Dependencies

From the root directory:

```
go mod download
npm install
```

### Database

Create a database, load the schema, and import the KJV text from `data/KJV`. The first line of `data/table_structure.sql` grants access to the production database user, so skip it locally:

```
createdb sharpsword_dev
grep -v '^grant ' data/table_structure.sql | psql -d sharpsword_dev
cd data
psql -d sharpsword_dev <<'SQL'
\copy books from 'KJV/books.tsv' with (format csv, delimiter E'\t', header true)
\copy verses from 'KJV/verses.tsv' with (format csv, delimiter E'\t', header true)
\copy paragraphs from 'KJV/paragraphs.tsv' with (format csv, delimiter E'\t', header true)
\copy descriptions from 'KJV/descriptions.tsv' with (format csv, delimiter E'\t', header true)
\copy headings from 'KJV/headings.tsv' with (format csv, delimiter E'\t', header true)
SQL
```

### Environment Variables

Create a `.env` file in the root directory:

```
PORT=3000
DATABASE_URL=postgres://localhost:5432/sharpsword_dev
```

## Development

Run the API and the frontend in two terminals from the root directory.

Start the Go API server on port 3000 (or `PORT` from `.env`):

```
air          # with hot reloading
go run .     # without
```

Start the Vite dev server for the Vue frontend:

```
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173). When served from `localhost`, the frontend sends API requests to `http://127.0.0.1:3000`.

Styles come from the committed `src/assets/output.css`. After using Tailwind classes that weren't used anywhere before, regenerate it with `npm run css`.

## Reading Plans

Plans that ship with the app are listed in `PLAN_CATALOG` in `src/assets/js/plans.js`. Each one points to a JSON file in `src/assets/plans/` that holds one array of USFM references per day, for example `["GEN.1", "PSA.119.1-88"]`. When someone starts a plan, a copy with their start date and progress is saved in `localStorage`.

To add a plan, put its JSON file in `src/assets/plans/`, add an entry to `PLAN_CATALOG`, and run `npm run validate:plans`. This checks that every reference is valid and that the plan covers every chapter.

## Production Build

`npm run build` builds the frontend into `public/`, which the Go server serves as static files alongside the API. Files that should be copied into the build unchanged, like the app install icons, go in `static/`.

### Offline Support

The build includes a service worker (generated by `vite-plugin-pwa`, configured in `vite.config.js`):

- **App files** are downloaded on install, so the app opens offline.
- **Chapters** are saved as they are read and refreshed in the background, so anything read once is available offline. Search needs a connection.
- **Save Bible** (in the About panel) downloads the whole KJV from `/api/v1/bible/kjv/all`, about 2 MB compressed, and saves every chapter into the same cache. The splitting logic lives in `src/assets/js/offline.js`.
- **Updates:** when a new version is deployed, open copies of the app show a "new version available" prompt instead of reloading on their own.

The service worker is off under `npm run dev`. To try it, run `npm run build` and open the Go server at http://localhost:3000.

The Go server sets `Cache-Control` headers for every response (`go/cache`):

- **`/assets/*`:** cached for a year, because the file names change with every build.
- **Bible text from the API:** cached for a day.
- **`index.html`, `sw.js` and the manifest:** checked on every load, so deploys show up right away.
- **`/api/v1/sync`:** never cached.

### Sync & Backup

Readers can back up their plans, highlights and history, and sync them between devices, from the About panel. There are no accounts; everything is tied to a sync key.

- **Encrypted in the browser:** the key is stretched with PBKDF2 into a vault id and an AES-GCM key (`src/assets/js/sync.js`). The server only sees the vault id, stores a hash of it, and keeps the encrypted snapshot. It can't read the data, and a lost key can't be recovered.
- **Records:** the data is stored as small timestamped records in localStorage (`src/assets/js/records.js`), and the newest copy of each record wins. Concurrent changes on different devices merge, and open tabs sync instantly through the `storage` event. `src/stores/userDataStore.js` turns the records back into the arrays the components use, and moves data saved by older versions over on first load, keeping the original under `ss.legacy-backup`.
- **Syncing:** `src/stores/syncStore.js` syncs 2 seconds after a change, when the app regains focus or comes back online, and every minute while it is visible. A save sends the version it was based on. If another device saved first, the server returns its copy to merge before retrying.
- **Server:** `go/api/vault` serves `GET`, `PUT` and `DELETE` on `/api/v1/sync`, with the vault id in the `X-Sync-Vault` header. Requests are rate-limited per vault and snapshots are capped at 1 MB. It creates its `sync_vaults` table on startup. If the database user isn't allowed to create tables, run the `CREATE TABLE` statement from `go/api/vault/vault.go` once by hand.

Font size, line height and last location stay per device.
